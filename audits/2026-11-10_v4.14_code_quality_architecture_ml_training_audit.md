## 1. Summary

1. **The newest work is not backed up.** The last local commit cannot be pushed to GitHub because it contains two 105.7 MB HTML bundles (limit 100 MiB). 4,222 lines of untracked code, 7 modified files and audits v4.9–v4.13 exist only on this external drive (`B39`).
2. **The dashboard can no longer start a training or a scan.** Every run it launches stops at the provenance gate, and a named custom polygon is rejected one step earlier by a region-name check (`B05`, `B06`). The same gate blocks the SageMaker entry point and every wrapper script.
3. **The dashboard is an unauthenticated remote control, and one script exposes it on all network interfaces.** A request can make it unpickle a model file from any directory on disk (`B01`, `B02`).
4. **Ten summary files on disk hold hard-coded metrics.** Three older runner scripts write fixed PR-AUC, ĉ and q̂ values as if they were measured, and one of those scripts also runs `git add -A` and `git push origin main` (`B03`, `B36`).
5. **Seven confirmed crashes or wrong outputs in live code paths**, each small to fix: `--head0-stacking off` crashes (`B04`), run deletion raises `NameError` (`B24`), PDF ingestion raises `NameError` (`B33`), coal-only runs report placeholder ĉ = 0.5 (`B08`), site cards label a threshold rule as a conformal set (`B07`), the run catalogue points into the old copy of the repository (`B25`), and the U-Net input cube can mislabel its channels (`B11`).
6. **The production validation split leaks.** It has no buffer and does not keep a deposit in one fold: 4 of 33 metal deposit clusters (12% of positive cells) are cut across folds (`B10`). The functions that would prevent this exist and are not called.
7. **One structural cause sits behind most pipeline defects.** The recipe "cells → fitted model → published numbers" lives inside one 2,221-line function and has been re-typed in the chunked inference path, the deposit-level harness, the in-script CV and eight runner scripts. The copies have drifted. §4.1 lists eleven refactors, in order.
8. **The unit suite passes (285 passed, 205 s) and cannot see any of this**, because it tests helper functions and nothing calls the orchestrator's main function, the server routes, or the UI builder.

Severity used below: **High** changes what a map or metric means, or risks data, code or the machine; **Medium** is a real defect with limited reach; **Low** is latent, cosmetic or in rarely used code.

## 4. Room for improvement

### 4.1 Architecture: eleven deepening candidates

Vocabulary: a **module** is anything with an interface and an implementation; it is **deep** when a lot of behaviour sits behind a small interface; a **seam** is where that interface lives. The numbers below are measured.

- `run_region_seven_pass` is 2,221 lines with 24 parameters; the orchestrator has 34 CLI flags and a 9-key settings dictionary.
- The lower bound has six definitions across the codebase; "which columns are features" is decided in six places; the 15 km distance cap is copied seven times; the propensity model has four implementations.

| # | Candidate | Strength | What hurts now | What would sit behind the interface |
|---|---|---|---|---|
| A1 | One scoring module | Strong | In-memory path, chunked path and CV harness score the same model three ways. Gates, ĉ, q̂ and blend weights are refitted on every run, including scan-only. | Everything between feature rows and published numbers: ensembles, gates, calibration constants, blend weights, conformal calibration, basin gate, missing-value policy. Saved and loaded as one thing. Whole-table and streamed scoring become two adapters. |
| A2 | One training-recipe module | Strong | `scripts/run_deposit_cv.py` "mirrors" the orchestrator by copy. Drift: harness defaults are the v4.7 settings and the orchestrator's are v4.8; the harness does not drop the seven regional features, fits the gate on all columns, caps access-column distances, and uses in-sample ĉ. A third copy (the in-script CV) uses 30 trees and 2 bags. | Cells, a training mask and settings in; a fitted run out. Feature selection, caps, propensity, exclusion halos, weights, gate and ensemble fitting. |
| A3 | A dataset-directory module | Strong | The cube contract is implied. 11 writers, 5 readers, one provenance writer. Features are chosen by exclusion: 83 columns give 50 features on the real cube. | Open a cube and get grid, an explicit verified feature list, labels and a chunk iterator; write layers only with a provenance record. |
| A4 | A region registry | Strong | About ten places map a region name to directories, resolution and block size. They disagree (`B05`); defaults point at cubes that fail the gate (`B06`). | Name or alias to dataset, run directory, grid, block size, title; one validity rule. |
| A5 | A run-directory module | Strong | The orchestrator writes 46 file names, most under two or three aliases; the server probes them in fallback order and builds its bundle five times with different keys; the archive copies the layout (`B25`, `B28`). | Write a run and read it back as one structure with a schema version and relative paths. |
| A6 | Quarantine the legacy runners (prerequisite) | Strong | Ten runner scripts keep the wide interfaces pinned, write fabricated numbers (`B36`) and one pushes to git (`B03`). | Nothing; this is moves and deletions. Two helpers (`fetch_terrarium_dem`, `get_kalimantan_land_tiles`) need a new home first. |
| A7 | An exploration-propensity module | Worth exploring | The two tested library functions cannot score new rows, so production wrote its own, which uses the covariates the library forbids. | Fit on training cells, keep state, score any rows, own the covariate policy. |

## 6. Checked and found sound

- `src/evaluation/deposit_cv.py`: small interface, model-agnostic, conservative on ties and non-finite scores. It is the best-shaped module in the repository and a model for the refactors above.
- The provenance gate (`assert_feature_provenance`) and `LayerStore` in `build_real_feature_cubes.py`: they refuse unrecorded layers as designed.
- Fit-on-train discipline for the propensity pipeline, the envelope gates and U-Net normalisation.
- Area in hectares on geographic grids (cosine-of-latitude error under 0.3% at these latitudes).
- The unit suite leaves the working tree untouched; test file writes go to temporary directories.
- The archive precondition: the canonical `calibrated_prospectivity.tif` and `site_cards.json` are written in every mode, so archiving is not skipped.
- Items listed as correct in v4.13 §7 were not re-audited.
