## 2. Physics Engine Audit: Contradictions, Fallacies & Bugs

### 2.1 Hanning Taper Applied Without Demeaning or Un-Tapering (`src/features/geophysics.py`)
- **Location:** [`_pad_and_taper`](file:///Users/gip/Geospatials/src/features/geophysics.py#L110-L143)
- **What the code does:**
  ```python
  padded = np.pad(filled, ((pad_r, pad_r), (pad_c, pad_c)), mode="reflect")
  taper = np.outer(np.hanning(padded.shape[0]), np.hanning(padded.shape[1]))
  return padded * taper, (slice(pad_r, pad_r + rows), slice(pad_c, pad_c + cols))
  ```
- **Physical & Mathematical Fallacy:**
  1. **No Mean/Trend Removal Before Windowing:** Total Magnetic Intensity (TMI) is $\sim 35{,}000\text{--}55{,}000\text{ nT}$ and Bouguer gravity is $\sim -150\text{ to }+100\text{ mGal}$. Multiplying a non-zero-mean grid by a 2D Hanning window forces the padded array to $0$ at the boundaries, creating an enormous artificial step/ramp across the entire grid.
  2. **Interior Signal Attenuation:** Because the Hanning window covers the **entire** padded array (`rows + 2*pad_r`), at the edges of the unpadded image (`r = pad_r`, where $pad\_r / (rows + 2 pad\_r) \approx 0.083$), $\text{hanning}(0.083) \approx 0.067$. The signal and its derivatives (`first_vertical_derivative`, `analytic_signal`, `upward_continue`) are attenuated by up to **$93\%$** near the raster borders and are never divided by the taper after `ifft2`!
  3. **Fix Required:** Subtract the planar trend or mean before padding, apply a cosine taper **only inside the padding margin** ($1.0$ across the entire interior slice `crop_slices`), and restore the mean if performing `upward_continue`.

### 2.2 Equatorial Reduction-to-Pole (RTP) Singularity & Azimuth Mirroring (`src/features/geophysics.py`)

### 2.3 Evans (1980) Plan Curvature Algebraic & Dimensional Error (`src/features/structural.py`)
- **Location:** [`plan_curvature`](file:///Users/gip/Geospatials/src/features/structural.py#L346-L409)
- **What the code does (Lines 398–406):**
  ```python
  D = (z_e + z_w) / (2.0 * d2) - z0 / d2           # 0.5 * d2z/dx2  [m^-1]
  E = (z_n + z_s) / (2.0 * d2) - z0 / d2           # 0.5 * d2z/dy2  [m^-1]
  F = (z_ne - z_nw - z_se + z_sw) / (4.0 * d2)     # d2z/dxdy       [m^-1]
  G = (z_e - z_w) / (2.0 * d)                      # dz/dx          [dimensionless]
  H = (z_n - z_s) / (2.0 * d)                      # dz/dy          [dimensionless]
  denom = G**2 + H**2
  curv = np.where(
      denom > 1e-10,
      -2.0 * (D * G**2 + E * F**2 - F * G * H) / denom,
      0.0,
  )
  ```
- **Mathematical Fallacy:**
  In Evans (1980) and Zevenbergen & Thorne (1987), plan (horizontal/contour) curvature measures curvature perpendicular to the slope vector $(G, H)$, so $D$ ($\partial_{xx}z$) must multiply $H^2$ ($z_y^2$) and $E$ ($\partial_{yy}z$) must multiply $G^2$ ($z_x^2$):
  $$\kappa_{\text{plan}} = -\frac{2\left(D H^2 + E G^2 - F G H\right)}{G^2 + H^2}$$
  Instead, the code wrote `D * G**2 + E * F**2 - F * G * H`:
  1. `D * G**2` projects along the gradient vector (profile curvature) rather than perpendicular to it (plan curvature).
  2. `E * F**2` multiplies the second derivative $E$ ($[\text{m}^{-1}]$) by the square of the mixed **second** derivative $F^2$ ($[\text{m}^{-2}]$) instead of $G^2$ ($[1]$), which is **dimensionally invalid** ($[\text{m}^{-3}]$ added to $[\text{m}^{-1}]$)!
  3. Because `f_curv = plan_curvature(...)` is used in [`run_borneo_features.py`](file:///Users/gip/Geospatials/scripts/run_borneo_features.py#L132) and [`run_indonesia_hd_upgrade.py`](file:///Users/gip/Geospatials/scripts/run_indonesia_hd_upgrade.py#L242) both as a direct feature (`dem_plan_curvature`) and to extract topographic lineaments (`curv_smooth >= np.percentile(curv_smooth, 86)`), this bug directly affects lineament extraction across all Indonesian and Kalimantan feature stacks.

### 2.4 Synthetic DEM-Derived Bouguer Gravity & Crustal Thickness Fallacy (`scripts/run_indonesia_hd_upgrade.py`)
