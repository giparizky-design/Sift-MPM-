# v4.15: Phase 2 of the v4.14 plan (T17–T21): labels, real cube, feature lists, propensity, validation split

**Date:** 2026-11-10 · **Timestamp:** 2026-11-10T21:25:00+08:00 · **Type:** Code and data change with measurements. Nothing was retrained or deployed; `outputs/seven_pass_*` and `data/kalimantan` (old cube) are untouched.

**What this is.** The five tasks of [v4.14 §5 Phase 2](2026-11-10_v4.14_code_quality_architecture_ml_training_audit.md) ("before any retrain"), implemented, tested, and followed by a rebuild of both real cubes and a deposit-level harness run. Decisions taken with the user: head 0 becomes copper only (key `porphyry_cu` kept); Busang is excluded; each cube was backed up and rebuilt in place; the harness was run.

**Tests.** Unit suite: **311 passed** (232 s), including 26 new tests (`test_v415_label_rules.py`, `test_v415_cube_fixes.py`, `test_v415_split_and_feature_lists.py`, plus two strike tests in `test_coal_and_multimodal_pipeline.py`). Five existing tests were adjusted to the new behaviour; see "Tests changed".

---

## 1. Summary

1. **The metal labels are now deposit records.** East Kalimantan (EK) has **one** copper deposit, so the "porphyry" head and the laterite head each have 1 held-out deposit and are reported `insufficient_data`. The island cube keeps 16 copper records.
2. **The optical "bare ground" layers are almost empty once water is removed.** `spec_clay_hydroxyl_gated` was valid on 174,924 EK cells, 90.6% of them with NDVI < 0; it is now valid on **7,392** cells (0.27%), none of them water. Those layers carried a water signal, not a bedrock signal.
3. **Td/Ts are now local.** They exist only within 5 km of a mapped fault (5.4% of EK cells), and are not in the default metals list.
4. **The propensity model uses roads, rivers and ports only** and can score any rows, so both inference paths and the harness use one model.
5. **The production split keeps each deposit in one fold and buffers 5 km.** Smoke run on the rebuilt EK cube: 14 of 289 positive clusters were cut across folds; now 0. The buffer removed 731 training rows (27 positive cells).
6. **Deposit-level result on the rebuilt EK cube (median-cell AUC, 15 km buffer, 4 seeds): 0.826 ± 0.003 for the 12-feature metals list.** The deposit set is smaller and different (19 clusters against 33), so this number is **not comparable** to v4.12's 0.861.

### T19: Td/Ts and pinned feature lists

- `build_structure`: Td and Ts use the GEM fault distance only (the 2.5 × DEM-lineament term is gone from them) and are NaN beyond `FAULT_MAX_DIST_M = 5000`. The site-card/ranking code already treats an all-NaN polygon statistic as 0, so no change was needed in `prospectivity_map.py`.
- New `config/features/metals_k4.txt` (12 columns) and `config/features/coal_k3.txt` (18 columns). `load_feature_list` in `src/schema/canonical.py`; the orchestrator takes `--feature-list-metals` / `--feature-list-coal` (defaults are those files; `none` restores automatic selection), the harness takes `--features-file`. A listed column that is absent or is a label, mask or label-derived column raises `ValueError`.
- **Deviation from the plan, stated plainly.** The plan said to generate the lists from "the automatic selection minus regional fields, Td/Ts and label-derived columns". That selection has 40 features and scores **0.765** at deposit level (§3, run P3), as the 44-feature default did in v4.12 (0.813 vs 0.861). I therefore pinned the **v4.12 14-feature set minus Td/Ts**, which is the set the evidence supports. The coal list is the v4.12 `COAL21` set minus Td/Ts, and **also excludes `dist_sedimentary_polygon_km` and `dist_marine_deltaic_contact_km`**, which come from the polygons that define the coal label rule (v4.12 §3, recommendation 3). That coal decision was not in the approved plan; revert it by adding the two columns back if you disagree.
- The orchestrator gives coal the union of the two lists (it has no per-domain feature exclusion); the lists are nested, so the union is the coal list.

### T20: propensity from roads, rivers, ports

- New layers `dist_roads_km` (public roads only) and `dist_ports_km` (OSM `ferry_terminal`; OSM has no port class, so this is a proxy and the provenance says so), plus `osm_water_mask`, `osm_quarry_mask`. `CANONICAL_PROPENSITY_COLS` is now `dist_roads_km`, `dist_major_rivers_km`, `dist_ports_km` (the old names existed in no cube).
- New `ExplorationPropensity` in `src/labels/pu_negatives.py`: fit once, score any rows; raises on a forbidden covariate or a missing column; same pipeline as production (median imputer, scaler, logistic C = 0.1). The orchestrator's 10-column list, the `ACCESS_KEYS` fallback and the flat 0.20 are gone; the chunked path scores with `prop_model.score(chunk_df)` and passes NaN to the imputer instead of zero-filling. The harness uses the same class (refit per fold) and no longer caps access distances at 15 km (ports reach 200 km).
- A dataset without the three columns now stops with `RealDataUnavailableError` rather than training on a substitute.

### T21: deposit clusters and a buffer in the production split

- `enforce_cluster_integrity` is applied before the folds; `training_buffer_exclusion` (same rule as `deposit_cv.training_exclusion_mask`) removes training cells within `--split-buffer-m` (default 5,000 m) of the held-out deposits, for the validation split and for the out-of-fold CV loops. `--cluster-integrity off` and `--split-buffer-m 0` restore the old split; `--legacy-v47` does both.
- `seven_pass_summary.json` now records `split_protocol`, `propensity_model`, `pinned_feature_lists` and `feature_columns`.

### 3.2 Deposit-level harness (`outputs/deposit_cv/v415/`, EK real cube, 15 km buffer, 5 folds, v4.8 switches as in v4.12)

Median-cell success-rate AUC (v4.10: the max-cell number has a null near 0.65 and is only in the JSON).

| Run | Features | Skarn (8) | Epithermal (10) | Any (19) |
|---|---|---|---|---|
| P1 pinned list, 4 seeds (42, 1, 2, 3) | 12 | 0.859 ± 0.003 | 0.714 ± 0.019 | **0.826 ± 0.003** |
| P1 logistic regression, seed 42 | 12 | 0.846 | 0.739 | 0.812 |
| P2 pinned + Td + Ts (new, fault-local), seed 42 | 14 | 0.859 | 0.723 | 0.835 |
| P3 automatic selection minus regional, Td, Ts, seed 42 | 40 | 0.723 | 0.729 | **0.765** |
| Coal, pinned list, seed 42 (270 clusters) | 18 | – | – | 0.743 (logreg 0.729) |

Porphyry (1 deposit) and laterite (1 deposit) are `insufficient_data` in every run.

**Reading.**
- The 12-feature list is far better than the automatic selection (+0.06 on "any", +0.14 on skarn), which reproduces the v4.12 finding on the corrected cube.
- Adding fault-local Td/Ts gave +0.012 on "any" at seed 42 only. The seed SD of P1 is 0.003, but I ran one seed of P2, and the deposit set is small; treat it as a lead, not a result. It is why Td/Ts stay out of the default list for now.
- The AUC of 0.826 against v4.12's 0.861 does not mean the model got worse. The skarn set shrank from 13 to 8 deposits (marble removed), the porphyry set from 10 to 1, and epithermal went from 11 to 10. Different deposits, different task.
- The coal labels are still generated from feature layers (v4.12 §3), so the coal number measures agreement with that rule; it is reported for completeness and means little.
- Epithermal at 0.71 is the weakest head and is still weak, as in v4.10/v4.12.

## 5. Not done, or found on the way

- **Not touched (outside Phase 2):** the cover-depth-from-e(x) fallback (v4.13 §5.2; it now changes target ranking through the new e(x)), `dist_active_faults_m` being mostly a terrain-curvature distance (v4.13 §2.2, still in the pinned list), the Bouguer/DEM issue, the coal label circularity, the lower-bound paths (C05), and B06/B37 (the dashboard and polygon cubes still build from legacy cubes, so they also lack `dist_roads_km` / `dist_ports_km` and now stop at the propensity check as well as at the provenance gate).
- **The EK window has one copper deposit.** A copper head for EK needs either the island cube (16 records) or a different scope; do not read per-head PR-AUC for heads 0 and 3 on EK.
- **OSM quarry polygons are a thin mine mask** (427 in the whole island). Coal pits mapped as `industrial` or not at all are missed; the AMD censoring and the coal label rule now see few mines.
- **The island cube** was rebuilt but not run through the harness.
- **`explored_footprint` is still built from the label buffers**, so the propensity target stays close to "is near a known deposit" (v4.14 facts for T20); only the covariates changed.
- **Docs:** `AGENTS.md` §3.2/§4.12 and `CLAUDE.md` were not edited; `AGENTS.md` still describes the old propensity and splits as resolved.
- **Backups** (`processed_v4.11/`, 4.3 GB) are kept; delete them when the new cubes are accepted.
- Nothing is committed.
