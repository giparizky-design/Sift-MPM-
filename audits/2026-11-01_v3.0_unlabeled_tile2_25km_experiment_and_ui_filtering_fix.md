Two critical root causes were identified and eliminated:
1. **JavaScript Boolean Evaluation Bug (`scripts/build_purged_ui.py`):** An expression evaluating `(sc.ore_category && sc.ore_category !== 'primary_target') || ...` returned the boolean primitive `true` instead of the string category `"coal_k0_high_cv"`. An adaptive percentile contrast stretcher was integrated into `_raster_to_rgba_base64` for moderate peak rasters ($P_{\text{max}} < 0.55$), mapping structural synclines into bright gold/yellow.

Concurrently, a second virgin $25\text{ km} \times 25\text{ km}$ ($250 \times 250 = 62{,}500$ cells @ 100m) greenfield block was selected in the **Central Kutai Fold Belt** (`UNLABELED_TILE2_25KM_100M`) and trained for 1 round of transfer adaptation. ## 2. Root-Cause Analysis of Dashboard "Only This?" Anomaly

### 2.1 The JavaScript Boolean Operator Precedence Bug
In [`scripts/build_purged_ui.py`](file:///Users/gip/Geospatials/scripts/build_purged_ui.py), lines 3454 and 3502 were previously written as:
```javascript
// BUGGY IMPLEMENTATION
const primaryOre = (sc.ore_category && sc.ore_category !== 'primary_target') || 
                   (sc.properties && sc.properties.ore_category && sc.properties.ore_category !== 'primary_target') || 
                   (conformalSet[0]) || "porphyry_cu";
```

Because `&&` has higher precedence than `||`, the first subexpression:
$$\text{sc.ore\_category} \land (\text{sc.ore\_category} \ne \text{'primary\_target'})$$
evaluates to:
$$\text{"coal\_k0\_high\_cv"} \land \text{true} \implies \mathbf{true} \text{ (Boolean Primitive)}$$
Consequently:
- `primaryOre` was assigned boolean `true`.
- `ORE_LABEL_MAP[true]` returned `undefined`.
- `ORE_COMMODITY_MAP[true] || "Polymetallic"` returned `"Polymetallic"`.
- `ORE_SYSTEM_MAP[true] || "Hydrothermal Mineral System"` returned `"Hydrothermal Mineral System"`.

When the user selected `ALL COAL BASIN RANKS (K=3)` in the UI dropdown, the filtering routine executed:
```javascript
passesOre = t.oreCategory.includes("coal"); // t.oreCategory === true
```
This threw `TypeError: t.oreCategory.includes is not a function`, terminating table filtering and marker rendering. All 49 targets were omitted from the viewport.

### 2.2 The Remediation
Lines 3453–3460, 3501–3508, 4047–4064, 4155–4172, and 4440–4458 in [`scripts/build_purged_ui.py`](file:///Users/gip/Geospatials/scripts/build_purged_ui.py) were refactored to use explicit type-safe string guards:
```javascript
const conformalSet = (sc.conformal_90pct_target_set || []).filter(x => x && !['primary_target', 'target'].includes(x));
let primaryOre = "porphyry_cu";
if (sc.ore_category && sc.ore_category !== 'primary_target') {
  primaryOre = sc.ore_category;
} else if (conformalSet.length > 0) {
  primaryOre = conformalSet[0];
} else if (sc.target_id && String(sc.target_id).toLowerCase().includes("coal")) {
  primaryOre = "coal_k0_high_cv";
}
```
And in all filtering routines:
```javascript
const oreCatStr = String(t.oreCategory || "").toLowerCase();
const structDomainStr = String(t.structuralDomain || "").toLowerCase();
const commodityStr = String(t.commodity || "").toLowerCase();
const targetSet = Array.isArray(t.conformalTargetSet) ? t.conformalTargetSet : [];

if (activeOreCategory === "coal_all") {
  passesOre = oreCatStr.includes("coal") || structDomainStr.includes("coal") || commodityStr.includes("coal") || targetSet.some(s => String(s).toLowerCase().includes("coal"));
}
```
This guarantees that `passesOre` is evaluated safely without throwing runtime TypeErrors, and properly maps the 49 targets in Tile #1 and 62 targets in Tile #2 to their appropriate coal basin classifications.
